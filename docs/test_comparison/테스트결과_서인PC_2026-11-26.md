## 관찰
1. **재정렬(C+)이 처음으로 효과를 보였다.** 후보가 40개로 늘자 blind-q018(r3) · chunk-c025(r4)가 재정렬 뒤 상위 5 안에 들어왔다. A+(r36 · r29)와 B+(r19 · r15)에서는 상위 5 밖이다. 이전에는 후보 20 밖이라 재정렬할 대상이 없었다. 다만 두 문항 모두 답 정답은 아직 x 다(사실 충족률 0.67 · 0.5).
2. **정답이 바뀐 문항은 대부분 순위가 같고 답만 달라졌다.** C+ 의 Q040 · Q045, A+ 의 Q009 · Q045 는 정답 청크 순위가 이전과 같은데 채점이 x → O 로 바뀌었다. 채점 메모를 보면 이전 답은 일부 사실을 '확인되지 않는다'고 했고, 이번 답은 네 사실을 모두 썼다. 생성 8개 · 부모 문맥(#43)으로 모델이 읽는 범위가 넓어진 효과로 보인다. 이번 C+ 는 정답 근거 문장이 모델 입력에 10/10 들어갔다.
3. **근거 없음 문항(blind-q039)을 C+ 가 처음으로 놓쳤다.** 답은 "병원 이름은 확인할 수 없다"로 맞게 시작했다. 하지만 "자료에 크리스틴 팔머에게 병원 치료를 받았다는 내용이 있다"는 문장을 덧붙였고, 채점이 이를 기준 답과 충돌한다고 봤다. 부모 문맥으로 주변 본문을 더 읽으면서 생긴 부작용일 수 있다. 상태가 `answered` 로 남는 문제(요약 0/1)는 이전부터 있던 팀 기준 미정 사항이다.
4. **순위가 같은데 결과가 뒤집힌 문항이 있다:** A+ 의 Q004 · minji-T003 은 O → x, B+ 의 Q015 는 x → O 다. 생성 · 채점 LLM 의 흔들림으로 본다. 이전 보고(#42 재실행)에서도 같은 조건으로 ±1 문항이 흔들렸다.
5. **응답 시간:** A+ · B+ 는 이전과 같은 3~4초대다. C+ 는 재정렬 시간이 줄어 A+ · B+ 와의 차이가 0.7~1.4초로 좁혀졌다. B+ 가 0.4초 느려진 원인(입력 토큰 증가 · API 응답 편차)은 이번 실행만으로는 나눌 수 없다.
6. 11문항이라 1문항이 10%p 다. 경향만 보고, 결론은 test 셋과 반복 실행 뒤에 낸다.

## 다음에 해 볼 것
- 설정 효과와 장치 효과를 나누려면 GPU 에서 이전 설정(`--generate-k 5 --pool 20 --context chunk`)으로 한 번 더 돌린다 (다른 PC 에서 진행).
