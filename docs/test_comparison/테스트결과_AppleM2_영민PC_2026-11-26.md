## 3. 서비스에 넣을 것

성능이 갈리는 단계는 재정렬뿐이다. 점수가 올라간 실행은 재정렬 장치가 빠른 동시에 생성 8 · 후보 40 · 부모 문맥을 쓴 ④ 다. 서비스 기본값(`SearchConfig.generate_k = 8`, `pool = 40`, 합집합 유지, 문맥 parent, `pick_device` 가 cuda → mps → cpu)은 그 방향과 같다. 이번 측정으로 손볼 곳은 아래 세 가지다.

| 적용 | 근거가 된 숫자 | 서비스에서 |
|---|---|---|
| 생성 8 유지 | M2 C+ 에서 Q004 · Q040 · minji-T003 이 6위. Hit@5 는 5/10, Hit@8 은 8/10. ④ C+ 는 생성 8로 Hit@8 10/10, 답 5/10 | 응답 경로의 `generate_k` 를 5로 내리지 않는다. ③ 맞춤 실험에서만 5를 쓴다 |
| 후보 40, 합집합 유지 | 후보 20이면 blind-q018 · chunk-c025 가 밖. ④ 는 재정렬 뒤 3위 · 4위. M2 에서 합집합만 남겨도 chunk-c025 가 30위 → 4위, Hit@5 6/10 | `pool` 40 과 합집합 유지를 응답 경로에 둔다. 잘게 자르는 비교 실행과 분리한다 |
| cpu 면 재정렬을 응답에서 빼기 | 후보 20 재정렬이 CPU 12.1초, MPS 2.4초. CUDA 는 후보 58~76에도 1.5초. 명석 PC 에서 후보 약 80개 1건은 49.4초 | `pick_device` 가 cpu 이면 C+ 대신 A+ 또는 B+ 로 답한다. mps · cuda 는 C+ 를 응답에 둔다. M2 는 후보 20에 재정렬 2.4초, 후보 29~39에 4.9초 |
| 부모 문맥은 두되, 근거 없음 답은 짧게 | ④ C+ 는 정답 문장이 입력에 10/10 들어갔고, 순위가 ③ 과 같은 Q040 · Q045 가 정답이 됐다. 같은 실행의 blind-q039 는 "병원은 확인할 수 없다" 뒤에 주변 문장을 붙여 채점이 실패 | parent 문맥은 유지한다. 근거 없음으로 답할 때는 부모 글의 주변 사실을 답에 붙이지 않는다 |

A+ · B+ 전체 시간은 세 기계가 3~4초다. 사용자 응답을 그 대에 맞추려면 재정렬 없는 구성을 두고, 가속기가 있을 때 C+ 를 더한다. C+ 단독으로 생성 5 · 후보 20 에 두면, 이번 M2 에서는 시간은 늘고 Hit@5 와 답 정답은 A+ 보다 낮다.
