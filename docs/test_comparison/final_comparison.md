명석 PC · 영민 PC(Apple M2) · 서인 PC 의 dev 평가 결과를 한 문서로 모았다. 서인 PC 에서 명석 PC ③ 과 **같은 설정**으로 GPU · CPU 를 한 번씩 더 돌려(⑤ · ⑥), 장치 효과와 설정 효과를 나눴다.

각 PC 의 자세한 기록은 같은 폴더의 `테스트결과_명석PC_2026-11-26.md` · `테스트결과_AppleM2_영민PC_2026-11-26.md` · `테스트결과_서인PC_2026-11-26.md` 에 있다.

## 한눈에
- **검색은 기계와 장치에 상관없이 똑같이 재현된다.** 같은 설정(생성 5 · 후보 20 · chunk)의 네 실행(③ · M2 · ⑤ · ⑥)에서 정답 청크 순위가 문항마다 같다. 다른 곳은 M2 A+ 의 minji-T003 하나(2위 ↔ 3위)뿐이다.
- **장치가 바꾸는 것은 재정렬 시간뿐이다.** 서인 PC 에서 같은 설정으로 C+ 재정렬이 GPU 0.5초, CPU 2.4초다. 점수 · 순위는 같다.

+            "cut_union": self.cut_union,   # 실행 기록 params 에 남긴다

# src/retrieve/pipeline.py — Retriever.first_stage
-        return rrf_merge(vector, self.bm25.search(query, config.pool), k=config.rrf_k)
+        merged = rrf_merge(vector, self.bm25.search(query, config.pool), k=config.rrf_k)
+        return merged[: config.pool] if config.cut_union else merged

# scripts/run_eval.py
+    parser.add_argument("--cut-union", action="store_true", help="합친 후보를 pool 개로 자르기")

## 5. 결론
1. **검색 파이프라인은 기계 · 장치가 달라도 같은 결과를 낸다.** 같은 색인 · 검색어 파일 · 설정이면 정답 순위가 재현된다. 기계 간 비교는 순위 · 검색 지표로 하면 된다.
2. **장치는 재정렬 속도만 바꾼다.** 점수 비교에서 GPU · CPU 를 나눌 필요가 없다.
3. **CPU 재정렬이 느린지는 장치 종류보다 기계 성능으로 판단한다.** 같은 CPU 재정렬이 2.4초(Core Ultra 9 275HX)에서 12.1초(i7-1360P)까지 나왔다.
4. **점수를 올린 것은 #43 설정(생성 8 · 후보 40 · 합집합 재정렬 · 부모 문맥)이다.** 같은 GPU 에서 ③ 설정 ⑤ 와 #43 설정 ④ 의 C+ 차이: Hit@5 5→7, Hit@8 8→10, 모델 입력에 정답 문장 6→10, 답 정답 3→5.
5. **답 정답 차이 ±2문항은 흔들림 범위다.** 순위가 같은 실행끼리도 A+ 답 정답이 2~4로 갈렸다. 답 정답으로 구성을 고르려면 test 셋과 반복 실행이 필요하다.
