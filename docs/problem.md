## 1. 한 줄 정의
마블 영화처럼 **작품끼리 이어진 영화 세계관**에서 입문자와 깊이 파는 팬이 겪는 "어디서부터 봐야 하는지 모르겠다 / 영화 사이의 관계와 사실을 확인하기 어렵다" 문제를, **출처가 붙는 근거 기반 답변**으로 돕는 Knowledge Agent.

## 2. 사용자
"덕후"는 서비스 이름이 아니라 **영화에 진심인 사용자**를 가리키는 표현이다. 주 타깃은 중·고수 덕후이고, 초보 덕후에게는 세계관과 관람 순서 안내를 준다.

| 사용자 | 상황 | 핵심 니즈 |
|---|---|---|
| **초보 덕후** | 세계관이 어려워 어디서부터 볼지, 무엇을 먼저 봐야 할지 모름 | 진입 경로, 쉬운 설명 |
| **중·고수 덕후** (주 타깃) | 여러 편을 봤고 연결·인물 이력·사건의 인과를 정리하고 싶음 | 정확한 사실과 **출처**, 영화 간 연결 |


## 3. 기존 탐색 과정 (팀의 가정)
1. 검색 엔진, 위키 문서, 커뮤니티 글에서 키워드로 찾는다.
2. 영화마다 문서가 따로 있고 목록·시간순·페이즈 문서가 흩어져 있어 여러 문서를 오가며 종합한다.
3. 누가 쓴 글인지, 언제 기준인지 확인하지 않은 채 정보를 믿거나 퍼뜨린다.

> 기존 탐색 시간은 측정하지 않았다. 따라서 **시간 절감률을 성과로 주장하지 않는다.**

## 4. 해결하려는 문제
| 문제 | 설명 | 받는 장치 |
|---|---|---|
| 정보 분산 | 영화·목록·시간순·배우 정보가 여러 문서에 흩어져 있음 | 한 색인 + 작품별 연결 카드 |
| 영화 간 관계의 복잡함 | 개봉순과 이야기 시간순이 다르고, 선행작·후속작·쿠키영상으로 이어짐 | 개봉 앞뒤 작품 · 타임라인 순번 · 쿠키영상 표시 |
| 비슷한 것의 혼동 | 비슷한 제목, 같은 캐릭터의 다른 시리즈, 배우 교체 | 정식 작품 여부를 적은 작품 카드 · 작품별 배우 |
| 일상어와 문서 용어의 차이 | "엔드게임 전에 뭘 봐야 해?"처럼 묻지만 문서에는 그렇게 쓰여 있지 않음 | 이름 사전 치환 + 쿼리 리라이트 |
| 출처 확인의 어려움 | 어디서 확인한 정보인지 알 수 없음 | 청크마다 작품 · 절 · 문단 번호 · 판 번호 |
| 확정과 추측의 혼재 | 루머, 추측, 스포일러가 섞임 | 문서 근거를 먼저 쓰고 · 문서에 없으면 웹 검색으로 보강하되 · 웹 결과는 따로 적재하고 "미검증"으로 표시 |

## 5. 질문 범위
답하는 범위는 **사실 · 연결 · 관람 순서**다. `[팀 확정]`

| 유형 | 예시 |
|---|---|
| 직접 검색 | "아이언맨 1편 쿠키 영상에 누가 나와?", "엔드게임 다음 개봉작이 뭐야?" |
| 표현 변형 | "엔드게임 보기 전에 꼭 봐야 하는 거 있어?" |
| 유사 조건 구분 | "헐크 역은 항상 같은 배우였어?", "2007년 닥터 스트레인지도 MCU야?" |
| 다중 근거 | "로키 드라마는 영화 어디와 이어져?" |
| 줄거리·연결 디테일 | "파워 스톤은 가디언즈 1편에서 어디를 거쳐 누구 손으로 갔어?" |
| **근거 없음** | "둠스데이 결말이 뭐야?"(미개봉), "데어데블 시즌 2 줄거리 알려줘"(2차 수집 범위), "마블에서 제일 강한 캐릭터는 누구야?"(주관 판정) |

- 대상 문서: **MCU 팬덤 위키**(Marvel Cinematic Universe Wiki)의 작품 문서. 공식 순서 문서 두 개에 오른 정식 작품 86편(시즌 단위) 가운데 **1차 수집 71편**이다 — 영화 44 · 마블 스튜디오 계열 시리즈 시즌 23 · 스페셜 3 · 단편 1. `[팀 확정]`
- 작품마다 Synopsis · Plot 절을 문단 단위로 넣고, 두 편 이상 나온 인물은 소개 문단을 넣는다.
- 정식이 아닌 작품과 미개봉작은 본문 없이 **한 줄 작품 카드**만 넣는다. 물으면 "MCU 정식 작품이 아니다" · "아직 개봉 전이다"를 카드로 답한다.
- 취향 기반 추천("가오갤 좋아하면 다음에 뭐 봐?")은 **시간이 남을 때의 시연용**이고 채점 대상이 아니다.

## 6. 오답·근거 부족의 영향
이 서비스의 오답은 사람을 다치게 하지는 않지만 다음 비용이 있다.

| 상황 | 영향 |
|---|---|
| 틀린 시청 순서·선행작 안내 | 이야기를 이해하지 못하고 시간을 낭비 |
| 틀린 감독·개봉일·배우 정보 | 커뮤니티 글이나 대화에서 오정보를 퍼뜨림 |
| 존재하지 않는 장면·연결을 있다고 안내 | 잘못된 기대, 신뢰 하락 |
| 문서에 없는 내용을 지어서 답변 | **"확인된 것만 말한다"는 서비스의 약속이 깨짐** |
| 개봉 전 영화를 개봉한 것처럼 안내 | 오보 |
| 스포일러를 묻지 않았는데 노출 | 사용자 경험 훼손 |

틀린 관람 순서와 지어낸 연결은 팬이 가장 빨리 알아채는 오류다. 그래서 **모르는 것은 모른다고 답하는 쪽을 오답보다 낫게 본다.**

## 7. 왜 RAG인가
모델이 마블을 이미 잘 알기 때문에 "모르니까 RAG"는 이유가 될 수 없다. RAG가 필요한 이유는 다음과 같다.

| # | 이유 |
|---|---|
| 1 | **최신성**: 모델의 지식은 특정 시점에서 멈추고, 새 개봉작과 일정 변경은 문서가 갱신된 만큼만 반영됨 |
| 2 | **그럴듯한 오답 방지**: 개봉일·감독·출연 같은 세부 사실을 근거 문서로 답하게 함 |
| 3 | **출처 확인**: 답변에 사용한 청크 ID와 원문 위치를 보여 줌 |
| 4 | **모르면 모른다고 하기**: 문서에 없는 질문에 지어내지 않고 근거 부족을 안내 |
| 5 | **버전 관리**: 위키 문서의 판 번호를 고정해 같은 결과를 재현·검증 |

| 대안 | 한계 |
|---|---|
| 모델 단독 답변 | 최신 정보 부족, 환각, 출처 없음 |
| 위키 검색창 | 일상어 질문과 문서 용어가 달라 한 번에 못 찾고 여러 문서를 직접 종합해야 함 |
| 문서 전체를 프롬프트에 삽입 | 길이 한계, 비용·지연 증가, 근거 위치 특정 어려움 |
| 파인튜닝 | 수업 범위 밖이고 문서가 바뀔 때마다 재학습 필요 |

**검색 기법은 문제의 성격에서 나온다.** 고유명사(영화·인물 이름)는 BM25가, 일상어 질문은 Vector가, 비슷한 작품 중 맞는 쪽은 re-ranking이 맡는다.

## 8. 제외 범위
- **넷플릭스 계열 13개 시즌**(데어데블·제시카 존스·루크 케이지·아이언 피스트·디펜더스·퍼니셔)과 **인물 전기 전체**의 본문 — 작품 행만 등록하고 본문 수집은 발표 뒤 2차로 미룬다
- MCU 정식 작품이 아닌 것의 본문, **미개봉작의 줄거리**, 코믹스·게임
- **포스터와 이미지** (저작권)
- 공식 사이트(Marvel.com · Disney+)와 IMDb의 **본문 수집** — 공식 사이트에서는 순서 값 · URL · 기준일만 적고, IMDb 가공본은 작품 표의 밑판으로만 쓰며 저장소에 올리지 않는다
- 사용자 작성 글(한 줄평, 외부 소셜 글)의 **RAG 색인 포함**
- 웹 검색 결과를 **고정 문서 색인에 섞는 것**과 검색된 페이지의 본문 수집 — 웹 결과는 제목 · URL · 요약 스니펫만 받아 별도 컬렉션에 넣는다
- 캐릭터 말투로 대화하는 기능, 취향 기반 추천의 정답 채점
- 모델 학습·파인튜닝, 실제 예매·결제 등 외부 시스템 쓰기
- 공개 배포·보안 인증을 달성했다는 주장

## 9. 성공 기준 `[팀 확정: 결과를 보기 전]`

### 9.1 우선순위
**품질 > 지연 > 비용** `[팀 확정]`
- 이유: 대화형 서비스라 체감 속도가 중요하고, 사용자 수가 적어 비용 영향은 작다. 단 품질(근거 있는 정확한 답)이 최우선이다.

### 9.2 비교 구성
| 구성 | 더하는 것 |
|---|---|
| 공통 | 이름 사전 치환 — 질문 속 한국어 작품·인물 이름에 영어 정식 이름을 덧붙인다 (규칙 기반, LLM 없음) |
| A | 벡터 검색 |
| B | + BM25 + RRF 결합 |
| C | + 재정렬 |
| C+리라이트 | + LLM이 질문 전체를 영어 검색어로 변환 (발제의 필수 최적화) |
| D | + LLM 가공 색인 (원문 색인과 따로 만든다) |

- 모든 구성에 같은 생성 모델 · 프롬프트 · 출력 한도를 쓰고, 컨텍스트는 상위 5청크다.
- C+리라이트와 D는 **각각 C에** 하나씩 더한 것이다. 둘 다 C와 견준다.
- 평가를 돌릴 때는 웹 검색 흐름을 끄고 고정 문서 컬렉션만 읽는다. 웹 청크가 평가 색인에 섞이면 구성 간 비교와 근거 없음 문항의 채점이 깨진다.

### 9.3 지표와 목표값 (예시 값, 팀이 합의해 확정)
| 지표 | 정의 | 목표(예시) |
|---|---|---|
| Hit@5 | 허용 근거 청크가 상위 5개 안에 하나 이상 (분모 17) | B ≥ A, C ≥ B |
| 정답 충족 | 필수 핵심 사실이 모두 맞고 모순 없음 (분모 17) | 0.7 이상 |
| 근거 적합 | 인용이 실제 검색 결과에 있고 주요 주장을 뒷받침 (분모 17) | 0.8 이상 |
| 근거 없음 대응 | 무근거 단정 없이 정보 부족 안내 (분모 3) | 3/3 |
| 호출 성공률·오류·timeout | 성공 수 / 전체 시도 | 기록 |
| 응답 시간 | 성공 호출의 평균·중앙값·n | 기록 |
| 추가 지표 | 토큰 사용량, 첫 토큰까지의 시간(TTFT) | 기록 |

### 9.4 도입 판단 규칙 (사전 확정)
튜터님 말씀대로 "품질이 조금 올라도 비용이나 지연이 크게 늘면 도입하지 않을 수 있다."
→ 예: **Hit@5나 정답 충족이 0.1 미만으로 오르는데 평균 응답 시간이 2배 이상 늘면 도입하지 않는다.** `[팀 확정]`
하이브리드나 re-ranking이 개선되지 않아도 결과 그대로 보고하고 원인을 분석한다.

### 9.5 일정이 밀리면 자르는 순서
① 취향 추천 → ② 웹 검색 경로 → ③ D 구성 → ④ 화면을 한 페이지짜리 최소 형태로. A · B · C와 C+리라이트 평가는 발제 필수라 자르지 않는다.

## 10. 채점 기준 개요
- 답변 가능 문항: 정답 충족 0/1, 근거 적합 0/1. 검색 실패는 Hit@5에서 0.
- 근거 없음 문항: 무근거 단정 없이 정보 부족을 안내했으면 1. **호출 오류는 올바른 거절로 세지 않는다.**
- 작품 카드로 답한 경우: 카드가 질문의 답 자체면 정상 답변이다("2007년 닥터 스트레인지는 MCU야?" → 아니다). 카드가 문서가 없는 이유만 말해 주면 근거 없음이다("둠스데이 결말이 뭐야?" → 개봉 전).
- 주관 판정 질문(예: 최강 캐릭터)은 **사실은 제시하되 우열을 단정하지 않으면** 1.
- 실패 유형을 구분해 기록: 검색 누락 / 순위 실패 / 생성 오류 / 잘못된 인용 / 근거 없음 대응 실패.
- 채점은 문항 작성자와 다른 팀원이 하고, LLM 판정을 쓰면 모델·프롬프트를 기록하고 사람의 검토와 구분한다.
- 정답 키의 근거는 청크 ID(`작품 + 절 + 문단 번호`)로 적는다. 짧은 문단을 합치는 기준(150자)이 번호를 바꾸므로 **이 기준을 먼저 고정하고** 문항을 쓴다.
- 세부 루브릭(핵심 사실 체크리스트)은 최종 실험 전에 확정한다.

|---|---|---|
| **메인(RAG 색인)** | MCU 팬덤 위키의 작품 · 시즌 · 인물 문서. MediaWiki API로 원문을 받고 문서마다 판 번호를 고정한다 | CC BY-SA (위키 API의 `rightsinfo`로 확인). 출처 표기와 동일 조건 공유 |
| 작품 표의 밑판 | IMDb 데이터에서 마블 작품만 정제한 가공본 132행 (ID · 한/영 제목 · 연도) | 개인·비상업 이용만 허용, **재배포 불가** → 저장소에 올리지 않고 다시 만드는 방법만 둔다 |
| 순서의 근거 | Marvel.com 「MCU Complete Timeline」(2026-10-22 기준) · Disney+ 「Marvel Movies In Order」(2026-11-04 기준) | 본문을 저장하지 않고 **순서 값 · URL · 기준일만** 적는다 |
| 보조(웹 검색) | 문서에 근거가 없을 때 Brave Search API로 조회한 결과의 제목 · URL · 요약 스니펫. 위키 청크와 같은 양식으로 바꿔 **별도 컬렉션**에 적재한다 | **평가에서 제외**, "웹 검색 결과 · 미검증"으로 표시. Brave 기본 약관 3(b)(i)은 검색 결과의 저장 · 캐시 · DB화를 금지한다 (2026-11-24 확인). **2026-11-25 저장 권한이 있는 요금제로 바꾸기로 팀이 합의**해 `WEB_STORE=true` 로 적재한다. 평가 · 벤치마크 사용 금지(3(b)(xiii))는 별개라 평가에서는 계속 끈다 |

- 문서마다 문서 ID, 제목, 출처 URL, 이용 조건, 판 번호, 수집 시점, 원문 위치를 문서 목록에 기록한다.
- 이미지는 사용하지 않는다. 가공본을 공개할 때는 CC BY-SA 조건(출처 표기, 동일 조건 공유)을 따른다.
- **LLM은 표의 칸을 채우는 데만 쓴다.** 청크의 본문은 위키 문단 그대로 두고, 링크·이미지 표기는 규칙으로 걷어낸다. 본문을 LLM이 다시 쓰는 것은 D 구성의 별도 색인에서만 한다.
- 도메인에 맞는 메타데이터: 작품 ID, 형식, 시즌, 개봉일, 개봉 앞뒤 작품, 타임라인 순번, 페이즈, 사가, 정식 작품 여부와 그 근거, 절 이름.
- 웹 검색 흐름: 한국어 질문을 영어 질의로 바꿔 PGVector를 먼저 조회하고, 근거가 없거나(미존재) 웹 보강을 한 적이 없으면(미보강) Brave Search를 부른다. 자세한 흐름과 양식은 `architecture.md` §6.
- 외부 검색 결과의 지시문은 신뢰할 수 없는 데이터로 취급하고 도구 권한을 주지 않는다. 검색어에 사용자 개인정보는 넣지 않는다.
- API 키는 `.env`로 관리하고 저장소(공개)에 올리지 않는다.

## 12. 가정과 한계
- 작은 평가셋(30문항)과 제한된 문서 범위(1차 수집 71편)의 검증이다. 실사용 성능이나 서비스 수준을 주장하지 않는다.
- 사용자와 불편은 팀의 가정이며, 기존 탐색 시간을 측정하지 않았다.
- 팬덤 위키는 팬이 편집하는 위키이므로 **공식 자료가 아니다.** 문서 내용과 수집 시점에 따라 실제와 다를 수 있다. 정식 작품 여부와 순서만 공식 문서에 기댄다.
- 색인은 영어 원문이다. 답변은 한국어로 쓰지만 화면의 근거 발췌는 영어로 보인다.
- 모델이 마블을 이미 알고 있어 정답 여부만으로는 RAG의 효과를 판단하기 어렵다. 근거 적합, Hit@5, 근거 없음 대응으로 따로 확인한다.
- 줄거리 요약 수준을 넘는 세세한 디테일(대사, 숨은 연결)은 문서에 없을 수 있고, 그 경우 "근거 없음"으로 안내한다.
- 선행작 후보는 출연진이 겹치는 정도로 계산한 **후보**이고, 쿠키영상 표시도 마지막 문단을 후보로 잡은 것이다. 둘 다 사람이 확인한 정답이 아니다.
- 웹 검색 결과는 누가 썼는지, 맞는지 확인하지 않은 글이다. 적재해 두면 오래된 내용이 다시 쓰일 수 있다. 그래서 문서 근거보다 뒤에 두고 항상 "미검증"으로 표시하며, 검색 기록이 유효 기간(`WEB_STORE_TTL_DAYS`, 잠정 30일. 결과 0건은 `WEB_STORE_EMPTY_TTL_DAYS`, 1일)을 넘으면 다시 검색한다.
- 검색 점수는 답변의 사실성 확률이 아니다.
